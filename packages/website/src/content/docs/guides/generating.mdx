The Tegaki generator processes fonts through a multi-stage pipeline to produce stroke data suitable for handwriting animation. Use the [studio](/studio/) on the Tegaki website to generate font bundles directly in the browser.

## Pipelines

The generator has two ways to find a glyph's strokes. Both start the same way: opentype.js extracts the path commands and metrics, and adaptive de Casteljau subdivision flattens the bezier curves into polylines.

### Geometry (default)

Works on the outline itself, with no bitmap:

1. **Mesh**: a conforming Delaunay triangulation fills the glyph's ink
2. **Ink graph**: the triangles' chordal axis gives each stroke's centerline, with its width read from the chords
3. **Spurs and nibs**: short offshoots at pointed ends and corners are pruned, and the ink they held is painted by an elliptic nib stamp as the pen passes
4. **Junctions**: where strokes meet, the arms are paired so a pen runs straight through a crossing instead of turning
5. **Simplify**: width-aware Ramer-Douglas-Peucker keeps the points the pen needs to cover the ink; leftover holes get stamps of their own
6. **Stroke order**: ordered by the reference glyph that fits the ink best, from [KanjiVG](https://kanjivg.tagaini.net/), [Make Me a Hanzi](https://github.com/skishore/makemeahanzi), the [Hershey fonts](https://github.com/kamalmostafa/hershey-fonts), [Letterpaths](https://github.com/RobinL/letterpaths) and composed Hangul (pick which in the Studio's **Pipeline → References**, or with `--reference-datasets`), or by your own drawing — draw a glyph's strokes in the Studio's **Reference** stage, Download the dataset, and pass it to the CLI with `--reference-file`; a letter whose shape misses them all still takes the pen direction a reference clearly prefers; otherwise top-to-bottom/left-to-right

### Raster

Rasterizes the glyph and thins it to a skeleton:

1. **Rasterize**: scanline fill with nonzero winding rule produces a binary bitmap
2. **Skeletonize**: Zhang-Suen thinning reduces the bitmap to 1px-wide skeleton
3. **Trace**: walks skeleton pixels into polylines, prunes short spurs, simplifies with Ramer-Douglas-Peucker
4. **Width**: a distance transform computes stroke width at each skeleton point
5. **Stroke order**: groups polylines into connected components, sorts top-to-bottom/left-to-right

### Stroke fonts (no pipeline)

Some fonts are already pen strokes: [Hershey's plotter fonts](https://github.com/kamalmostafa/hershey-fonts), the single-line SVG fonts made for pen plotters and engravers ([Evil Mad Scientist's](https://gitlab.com/oskay/svg-fonts) Hershey and EMS faces, [Relief SingleLine](https://github.com/isdat-type/Relief-SingleLine)), or a stroke-order dataset you drew in the studio. Nothing is extracted from them: their strokes go into the bundle as they are, in the font's own order and direction, drawn with a round pen of the width you pick. Tegaki then makes a font file from the strokes (each glyph's outline is its strokes as the pen draws them, at the font's advance widths), so the renderer lays out, wraps and clips the text as it does for any bundle — every effect and plugin works on them.

In the studio, pick one from **Single-line fonts** in the font picker (or upload an `.svg` font, a `.jhf` file or a `.strokes.json` dataset) and set the pen in **Pipeline → Stroke font**. From the CLI:

```bash
bun start generate --stroke-font EMSAllure.svg --pen-width 0.06 -o output/ems-allure
```

`-c` narrows the characters (default: every glyph in the font), and `--drawing-speed` / `--stroke-pause` time the strokes as for the pipelines. The font's credits and license, which single-line fonts carry in their metadata, are written beside the bundle as `LICENSE.txt`.

## Options

| Option | Default | Description |
|--------|---------|-------------|
| Font | `Caveat` | Google Font family name |
| Characters | `A-Za-z0-9` + punctuation | Characters to process |
| Pipeline | `geometry` | Stroke extraction: `geometry` or `raster` |
| Resolution | `400` | Bitmap resolution for rasterization (raster) |
| Skeleton method | `zhang-suen` | Skeletonization algorithm (raster) |
| Line cap | `round` | Stroke line cap style |
| Bezier tolerance | `0.5` | Flatness tolerance for bezier subdivision |
| RDP tolerance | `1.0` | Ramer-Douglas-Peucker simplification tolerance (raster) |

## Output format

The generator outputs a compressed format with short keys to minimize bundle size. Per-glyph data includes `w` (advance width), `t` (total animation duration), and `s` (strokes). Each stroke has `p` (points as `[x, y, width]` tuples), `d` (delay), `a` (animation duration), and, for geometry strokes that carry them, `n` (nib stamps as `[pointIndex, dx, dy, major, minor, angle]`). See the `TegakiGlyphData` type for full details.
